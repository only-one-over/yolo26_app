# v1.0.3 发布说明

发布日期：2026-08-03

## 概要

v1.0.3 新增 Windows `CUDA-Full` 离线便携包，并保留原有 CPU 与 CUDA 包。CUDA-Full 面向有 NVIDIA GPU 的离线使用场景，内置 YOLO26 n/s 检测权重、SAM2.1 Hiera Tiny 权重和 SAM2 运行依赖。普通 PyPI 包仍保持轻量，不包含模型权重、CUDA、SAM2 或 Windows 运行时。

## 下载哪个包

| 包 | 适用场景 | 是否需要 NVIDIA GPU | 内置内容 |
| --- | --- | --- | --- |
| `YOLO26-App-CPU` | 仅 CPU 的标注、训练和推理 | 否 | Python 运行时和基础应用依赖 |
| `YOLO26-App-CUDA` | 已有 GPU 环境，按需下载模型 | 是 | CUDA 12.1 PyTorch 和基础应用依赖 |
| `YOLO26-App-CUDA-FULL` | 无网络或希望开箱使用 YOLO26/SAM2 | 是 | CUDA 12.1 PyTorch、SAM2 兼容运行时、YOLO26 n/s、SAM2.1 Tiny |

`CUDA-Full` 体积明显更大；若只使用普通 YOLO 推理或不需要 SAM2，优先选择 CPU 或 CUDA 包。

## CUDA-Full 包含什么

- `yolo26n.pt`：YOLO26 Nano 检测权重，适合快速推理和轻量训练起点。
- `yolo26s.pt`：YOLO26 Small 检测权重，精度与资源占用更均衡。
- `sam2.1_hiera_tiny.pt`：SAM2.1 Hiera Tiny 交互分割权重。
- 固定提交的 SAM2 Python 依赖，以及 `sam2_configs`、Hydra、OmegaConf、iopath 等运行资源。
- CUDA 12.1 对应的 PyTorch 2.5.1 和 torchvision 0.20.1。

应用首次启动会在后台将内置模型复制到用户工作区的 `system_model/yolo/` 和 `system_model/sam2/`。复制期间，训练和 SAM2 标注仍可直接使用包内的只读模型；已有的用户模型或自训练模型不会被覆盖。

## 使用方式

1. 从 [v1.0.3 Release](https://github.com/only-one-over/yolo26_app/releases/tag/v1.0.3) 下载对应包及其 `.sha256` 文件。
2. CPU 包直接解压后启动 `YOLO26-App-CPU.exe`。
3. CUDA 或 CUDA-Full 包要求目标电脑具有兼容的 NVIDIA 显卡和驱动；无需额外安装 CUDA Toolkit。
4. 完整解压压缩包后启动对应 `.exe`，不要只移动 `.exe` 文件。
5. 在“训练”页选择 YOLO26 n 或 s 时，CUDA-Full 会优先使用内置权重，不触发 Ultralytics 自动下载。
6. 在“标注”页使用 SAM2 时，选择 Tiny 模型即可使用内置 `sam2.1_hiera_tiny.pt`。

## 分卷压缩包

CUDA 和 CUDA-Full 超过 GitHub 单个附件大小限制，发布为多个 `.zip.partNNN` 文件。下载同一包的所有分卷、`.zip.sha256` 与 `.reassemble.ps1` 到同一目录，执行：

~~~powershell
powershell -ExecutionPolicy Bypass -File .\YOLO26-App-CUDA-FULL.reassemble.ps1
Expand-Archive .\YOLO26-App-CUDA-FULL.zip
~~~

CUDA 包使用同名的 `YOLO26-App-CUDA.reassemble.ps1`。重组脚本会先校验 SHA-256，再解压。

## 不包含的组件

- TensorRT：必须根据目标机器的 GPU、驱动和 CUDA 环境单独安装。
- YOLOv8 权重：仍可由用户按需下载或导入。
- SAM2 Small、Base+、Large：仍为按需下载模型。
- Grounding DINO、RealSense：保持为可选组件。

SAM2 以不编译自定义 CUDA 扩展的兼容模式打包，避免目标设备要求 NVCC。核心图像交互分割可用，但它不是针对所有高级视频功能的性能优化构建。

## 修复与改进

- 修复训练完成后结果摘要遮挡训练曲线的问题：曲线默认保持显示，结果摘要由“查看训练结果”展开。
- 增加内置模型清单、固定下载 URL 和 SHA-256 校验，防止构建时下载到未受控的权重文件。
- 增加 CUDA-Full 构建资源检查，兼容 PyInstaller 的根目录与 `_internal` 两种包布局。
- 修复 Windows UI 测试中强制处理 Qt 延迟销毁可能导致的原生访问冲突。

## 已知事项

- PyPI 发布依赖 PyPI Trusted Publisher 配置。若 PyPI 工作流显示 `invalid-publisher`，请参照 [PyPI Trusted Publisher 排障文档](https://docs.pypi.org/trusted-publishers/troubleshooting/) 核对项目、仓库、工作流和 `pypi` Environment。
- Windows 便携包与 PyPI 发布相互独立；PyPI 发布失败不会影响 GitHub Release 的 Windows 包下载。
